Keep the existing constants (`$ImageName = "finally"`, `$ContainerName = "finally-app"`, `$VolumeName = "finally-data"`, `$Port = 8000`), the `$ScriptDir`/`$ProjectRoot` resolution, the `docker run` flags, and the existing filter quoting `"name=^${ContainerName}$"`, which works today.

    Four PowerShell 5.1 specifics, all from the pattern map:
    - Probe with `Invoke-WebRequest -UseBasicParsing -Uri "http://localhost:$Port/api/health"` wrapped in `try`/`catch`. PowerShell 5.1 needs `-UseBasicParsing`, and a non-2xx response throws, so the catch branch is the retry path. Do not use `curl`, which is an alias for `Invoke-WebRequest` in 5.1 and takes different arguments.
    - `$ErrorActionPreference = "Stop"` does not stop on a native command's non-zero exit, so check `$LASTEXITCODE` explicitly after `docker build` and after `docker run` and exit non-zero if either failed.
    - Dump only the container's own application log output; never the container environment or its config, which would echo the API key.
    - Keep the poll budget, the log-tail count, and the user-facing message text byte-identical to the mac script so the two platforms are genuinely the same tool.

    Then confirm `scripts/stop_windows.ps1` already matches `scripts/stop_mac.sh`: it exits 0 with a message when nothing is running, removes only the anchored container, and never mentions a volume. The pattern map expects no change; the only noted divergence is that mac swallows stop/rm failures while Windows does not, which is immaterial in 5.1 because native failures do not throw. Leave that alone.

    Record in the summary that DEP-04 is verified by reading and source assertions only and remains unverified on Windows (D-10).
  </action>
