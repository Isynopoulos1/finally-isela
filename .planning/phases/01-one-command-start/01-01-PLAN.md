## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host filesystem → image build context | `.env` and `db/*.db` sit in the build context and could be copied into a layer |
| host → container (published port) | `-p 8000:8000` binds `0.0.0.0`, exposing the unauthenticated API to the local network |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

| T-01-03 | Elevation of Privilege | container process runs as uid 0 (confirmed at planning time) | medium | accept | ASVS L1, single-user local dev container on loopback with no untrusted tenant; adding a non-root user is out of scope for this phase and is recorded here so a later hardening phase can pick it up |

| T-01-05 | Denial of Service | HEALTHCHECK probe loop | low | accept | stdlib `urlopen` against loopback every 10s with a 3s timeout; negligible load, no external network call |
| T-01-SC | Tampering | `npm install` / `uv sync` in the image build | medium | mitigate | this phase introduces NO new packages; `uv sync --frozen` pins from the committed `backend/uv.lock` and npm installs from the committed `frontend/package-lock.json`.
